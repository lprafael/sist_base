Ficha de Implementación: Mensajería Programada

Registro técnico y plan de arquitectura ejecutado para el Módulo de Mensajería del Sistema Integral de Gestión Electoral (SIGEL).

Implementación Finalizada

Introducción y Objetivos

El Módulo de Mensajería de SIGEL permite a los candidatos parametrizar, agendar y redactar plantillas de mensajes para ser enviados de manera masiva o personalizada. Los placeholders se autocompletan en tiempo real con datos de las tablas del padrón y simpatizantes.

Dos Universos de Envío

1) Mis Seguidores: Simpatizantes captados que apoyan al candidato actual.
2) Padrón Completo: Todos los registrados en el censo electoral de un departamento, distrito o local de votación (disponible para administradores y candidatos principales).

Arquitectura de Ejecución

Para evitar sobrecargar el entorno con dependencias externas como Redis o Celery, se optó por un motor de sondeo asíncrono utilizando APScheduler. Este motor corre dentro del mismo bucle de eventos de FastAPI y actualiza el progreso en lotes de 20 mensajes.

Estructura de la Base de Datos

Se crearon dos tablas en el esquema electoral para la gestión y bitácora de auditoría:

Tabla electoral.mensajes_campania

Almacena la cabecera de la campaña, la plantilla del mensaje, filtros territoriales y estadísticas acumuladas de envío.

CREATE TABLE electoral.mensajes_campania (
    id SERIAL PRIMARY KEY,
    nombre_campania VARCHAR(150) NOT NULL,
    tipo_destinatario VARCHAR(30) NOT NULL, -- 'seguidores' o 'padron_completo'
    canal VARCHAR(20) NOT NULL, -- 'sms', 'whatsapp', 'email', 'n8n'
    plantilla_mensaje TEXT NOT NULL,
    fecha_programada TIMESTAMP WITH TIME ZONE NOT NULL,
    estado VARCHAR(20) DEFAULT 'pendiente', -- 'pendiente', 'en_progreso', 'enviado'
    total_destinatarios INTEGER DEFAULT 0,
    enviados_exito INTEGER DEFAULT 0,
    enviados_fallido INTEGER DEFAULT 0,
    creado_por INTEGER REFERENCES sistema.usuarios(id) ON DELETE SET NULL,
    eleccion_id INTEGER REFERENCES electoral.elecciones(id) ON DELETE CASCADE,
    filtros JSONB,
    fecha_creacion TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

Tabla electoral.mensaje_destinatarios

Bitácora de auditoría individual. Registra el mensaje final traducido y el estado/error de la API de comunicación.

CREATE TABLE electoral.mensaje_destinatarios (
    id SERIAL PRIMARY KEY,
    campania_id INTEGER REFERENCES electoral.mensajes_campania(id) ON DELETE CASCADE,
    cedula VARCHAR(20) REFERENCES electoral.personas(cedula) ON DELETE SET NULL,
    telefono VARCHAR(20),
    email VARCHAR(100),
    mensaje_personalizado TEXT NOT NULL,
    estado VARCHAR(20) DEFAULT 'pendiente', -- 'pendiente', 'enviado', 'fallido'
    fecha_envio TIMESTAMP WITH TIME ZONE,
    error_mensaje TEXT
);

Motor del Planificador (scheduler.py)

El backend utiliza un bucle asíncrono para ejecutar los envíos. A continuación se detalla la lógica clave de reemplazo de placeholders definidos por llaves individuales:

def construir_mensaje_personalizado(plantilla: str, persona: dict) -> str:
    mapeo = {
        "{nombre_apellido}": f"{persona.get('nombres', '')} {persona.get('apellidos', '')}".strip() or "Votante",
        "{local}": persona.get("nombre_local") or "No asignado",
        "{mesa}": str(persona.get("mesa", "Sin mesa")),
        "{candidato}": persona.get("nombre_candidato") or "Candidato"
    }
    mensaje = plantilla
    for tag, valor in mapeo.items():
        mensaje = mensaje.replace(tag, valor)
    return mensaje

Endpoints API Registrados

Se crearon y montaron los siguientes endpoints REST en el router de FastAPI (mensajeria_routes.py):

  • POST /api/mensajeria/campanias - Crear y programar una campaña.
  • GET /api/mensajeria/campanias - Listar campañas históricas y activas.
  • GET /api/mensajeria/campanias/{id} - Obtener estadísticas de progreso en vivo.
  • DELETE /api/mensajeria/campanias/{id} - Eliminar o cancelar una campaña en estado 'pendiente'.
  • GET /api/mensajeria/campanias/{id}/destinatarios - Obtener bitácora detallada de envíos.
  • POST /api/mensajeria/preview - Renderizar una plantilla de prueba con datos mock.

Interfaz del Dashboard React

El componente frontend principal se ubica en frontend/src/components/MensajeriaDashboard.jsx. Ofrece una experiencia interactiva completa:

  • Métricas Generales: Tarjetas con el total de campañas, mensajes entregados con éxito y fallidos.
  • Inserción Inteligente: Botones rápidos para inyectar variables en la posición del cursor de texto.
  • Segmentación Jerárquica: Dropdowns geográficos encadenados (Departamento → Distrito → Local) que cargan dinámicamente opciones del servidor.
  • Vista Previa Celular: Maqueta visual interactiva de un teléfono smartphone para ver cómo lucirá el mensaje según el canal seleccionado (SMS, WhatsApp o Email).
  • Bitácora en Vivo: Consulta detallada de errores de red y estados de cada destinatario.
